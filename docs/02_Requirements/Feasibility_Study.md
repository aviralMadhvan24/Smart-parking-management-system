# Feasibility Study

## 1. Technical feasibility
A web application using React, Express, Node.js, and MongoDB is feasible for a student team familiar with JavaScript. Authentication, CRUD APIs, and reservation validation are supported by common libraries. Physical sensor integration and robust concurrent reservation handling add complexity and are not required for the first prototype.

**Assessment:** Feasible for an academic prototype, provided the scope remains limited.

## 2. Economic feasibility
The prototype can be built using open-source development tools and a local database. Optional hosting may have free or low-cost tiers, subject to provider limits. Costs may include domain name, paid hosting, SMS/email usage, or hardware if added.

| Item | Estimated cost | Notes |
|---|---:|---|
| Development tools | ₹0 | Open-source tools assumed |
| Local database | ₹0 | Local development assumed |
| Hosting | ₹0–₹1,500/month | Illustrative only; check current provider prices |
| Domain | Optional | Depends on provider and extension |
| IoT sensors/barrier | Excluded | Future scope |

**Assessment:** Economically feasible as a software-only student project.

## 3. Operational feasibility
Drivers use a browser to check and reserve parking. Administrators maintain slot data and update entry/exit status. Training requirements are low, but data accuracy depends on staff updating records promptly.

**Assessment:** Feasible for a campus demonstration or small parking facility.

## 4. Schedule feasibility
A small team can complete requirements, design, implementation, testing, and documentation over approximately 6 weeks. The schedule is illustrative and must be adjusted to the actual deadline.

## 5. Legal, privacy, and ethical considerations
Collect minimal user data, protect credentials, avoid exposing personal details, and obtain permission before using real facility data. Do not store actual payment-card data. Follow applicable institutional policies and local law.

## 6. Conclusion
The proposed system is feasible if real-time sensors, physical gate automation, and real payments remain outside the first version.
