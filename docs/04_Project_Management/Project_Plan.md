# Project Plan and Schedule

**Project:** Smart Parking Management System  
**Planned duration:** 6 weeks (illustrative)  
**Project lead:** [Name]

## 1. Work breakdown structure
| Phase | Tasks | Deliverable |
|---|---|---|
| 1. Initiation | Define problem, stakeholders, scope, success criteria | Proposal and scope |
| 2. Requirements | Elicit, prioritize, review requirements | SRS and stakeholder requirements |
| 3. Design | Architecture, data model, UML, API design | SDS and diagrams |
| 4. Implementation | Auth, parking inventory, reservations, admin workflows | Source code |
| 5. Verification | Unit/API/manual tests, bug fixing, regression testing | Test results and traceability |
| 6. Release/documentation | Setup guide, user manual, screenshots, final report | Submission package |

## 2. Schedule
| Week | Planned activities | Exit criteria |
|---|---|---|
| 1 | Proposal, scope, stakeholder analysis | Scope approved |
| 2 | SRS, feasibility, use cases | Requirements reviewed |
| 3 | Architecture, UML, database design | Design reviewed |
| 4 | Core implementation: auth, lots, slots | Core CRUD works |
| 5 | Reservations, admin workflows, testing | Core tests executed |
| 6 | Fixes, screenshots, manuals, final report | Submission checklist complete |

## 3. Milestones
- M1: Scope baseline approved.
- M2: Requirements baseline approved.
- M3: Design baseline approved.
- M4: Core workflow implemented.
- M5: Test execution completed.
- M6: Final submission package reviewed.

## 4. Change management
Each proposed change should include its reason, priority, affected requirement IDs, estimated effort, and impact on tests. The project lead and faculty guide (if required) approve changes before the baseline is updated.

## 5. Progress tracking
Update status weekly using `Not Started`, `In Progress`, `Blocked`, or `Done`. A task is only `Done` when its deliverable has been reviewed.
