# Stakeholder Requirements

| Stakeholder | Need | System response | Priority |
|---|---|---|---|
| Driver | Know which slots can be reserved | Show current application status and time-window availability | High |
| Driver | Reserve a slot without duplicate allocation | Validate conflicts on backend | High |
| Driver | See and cancel own reservations | Provide reservation history and cancellation rules | High |
| Parking administrator | Maintain parking inventory | CRUD and activate/deactivate lots and slots | High |
| Parking administrator | Know current occupancy | Dashboard counts and reservation list | High |
| Parking administrator | Record vehicle entry/exit | Check-in/check-out workflow | High |
| Project evaluator | Verify engineering process | SRS, design, test evidence, traceability | High |
| Maintainer | Set up and troubleshoot system | Installation guide, environment example, logs | Medium |
| Future operator | Use physical sensor data | Integration interface as future enhancement | Low / future |

## Stakeholder validation questions
- What is the cancellation deadline?
- Are walk-in vehicles supported?
- Are different slot types or rates needed?
- Is the parking fee flat-rate, hourly, or capped?
- Should users be able to reserve immediately or only for future time windows?
- Is an administrator manually recording occupancy, or will sensors eventually provide it?

Record the answers from your actual project supervisor before final submission.
